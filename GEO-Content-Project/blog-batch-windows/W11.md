## How these pages are built (this is not what the batch brief implies)

`src/pages/blog/<slug>.astro` is a **23-line wrapper**. It holds only the `title=`,
`description=`, `canonical` and the schema wiring. **All the prose lives in
`pages/blog/<Component>Page.tsx`** — a hand-written React page of 430–670 lines, with:

- `export const articleSchema = generateArticleSchema({ headline, description, url, datePublished })`
- `export const faqItems: FAQItem[] = [...]` — the FAQ, and the source of the FAQ schema
- a `<h1>` in the header block
- a "Contenido del artículo" table-of-contents `<ul>` of `#anchor` links
- an intro `<p className="text-lg text-gray-700 mb-8 leading-relaxed">`
- `<section id="...">` blocks, each opening with
  `<h2 className="text-2xl md:text-3xl font-bold text-gray-900 mb-6">`

**So a fix usually touches three or four places:** the `.astro` title/description, the component's
`articleSchema` headline/description, the `<h1>`, the intro paragraph, and — if you add a section —
the TOC list plus a new `<section>`.

### Rules for editing these files

- **Reuse the class strings already in the file.** Copy an existing `<section>`/`<h2>`/`<p>` and
  change the words. Introduce no new markup patterns and no new colour tokens.
- **Keep `faqItems` shape exactly:** `{ question, answer }`, typed `FAQItem[]`, imported from
  `utils/schemaData`. Never rename the keys, never define the interface locally — the build
  validates this and will fail.
- **If you add a `<section id="x">`, add its `#x` link to the TOC list** or the page gets an orphan
  anchor.
- **Titles:** keep `fullTitle={true}` where it is already set and stay **≤ 60 characters**. Where it
  is *not* set (F5 `escala-cambridge` has it, but several Tier B pages do not), `BaseLayout` appends
  the brand chain and hard-truncates at 70, which has already shipped five mid-word titles. If you
  change a title on a page without `fullTitle`, add it.
- **`verify:design` does not scan `pages/blog/*.tsx`**, so there is no token-debt risk here. Do
  **not** touch `components/PAAArticlePage.tsx`, which *is* scanned.
- **Do not run `npm run build`, `verify:design` or `astro check`** — shared working tree; the final
  gate does it.

### ⚠️ Read the page before you edit it

The batch brief's diagnosis comes from **GSC query data**, not from a re-read of the page. Some of
these pages already partly do what the fix asks. F2, for instance, already contains "La respuesta
corta es no: el certificado C1 Advanced no caduca nunca" — buried in the *second* sentence behind
"Una de las preguntas más frecuentes...". So the fix there is *promotion*, not addition.

**Open the component, read the intro and the H2 list, then decide what the edit actually is.** If a
fix turns out to be already done, say so in the ledger with `NOOP` instead of inventing an edit.
